# When a simulation adds value

Use ordinary source-grounded critique for a few hypothetical objections.
Install no simulator merely to make a council appear more independent.

For repeatable small persona or product scenarios, the reviewed conditional
candidate is [Microsoft TinyTroupe](https://github.com/microsoft/TinyTroupe/tree/7ce8be378a37ee73f9745d6781452712318afa04)
(MIT, Python ≥3.10). It has comparison and cost utilities, but broad dependencies
and experimental local-model support. Empirical comparisons in its
[preprint](https://arxiv.org/html/2507.09788v3) do not validate a new scenario.

For explicit environment rules or persistent multi-party state, consider
[Concordia](https://github.com/google-deepmind/concordia/tree/15169db65cb00e9eadc126ecf19fe8aa6142e6f6)
(Apache-2.0, Python ≥3.12). It needs scenario and embedding engineering.
[OASIS](https://github.com/camel-ai/oasis/tree/fced8869353f858de4ebe7b8f60321415f238fad)
(Apache-2.0) is for social-network propagation research.

[MiroFish](https://github.com/666ghj/MiroFish/tree/7657031ac01184afe2cb220f5ee3545573b5e843)
(AGPL-3.0) adds a complete web/graph stack and requires Zep Cloud plus LLM
access in this revision. It is not the default for a reasoning-bias problem.
Its prediction language is not proof of calibrated forecasting.

Activate one runtime only for a concrete scenario with value beyond direct
critique: use authorized inputs, an available local model or approved provider
and budget, bounded agents/rounds/calls, a direct baseline and retained traces.
Label outputs hypothetical. Compare with real observations before any claim
about users, population behavior, forecasts or reduced bias. No simulator,
model weights, cloud connection or new memory system is installed by this skill.
