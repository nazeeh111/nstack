# Source fidelity

Install the selected upstream method and its required support. Preserve its steps,
roles, defaults, examples and metadata. Native bindings should be small, use the
current host and preserve the user's model/settings. Do not replace a complete
method with a generic summary or add a second workflow around it.

nstack records exact GitHub repositories and commits. Original files, source
hashes and explicit patches distinguish unchanged content from adaptations.
Some catalog sources identify tools or command guides rather than skills; those
need a labelled entrypoint to the actual source. Where a matching upstream skill
exists, use it. Skill Seekers and Slidev now use their real upstream skills;
Impeccable uses its selected generated command methods. The catalog's original
source tuple and actual method path are both recorded.

The source-fidelity pass restores methods previously changed unnecessarily,
including reproduction/minimization, academic routing and independent review,
Council rules, visual passes, complete security references, training recipes,
SEO/ads domain review and original render/preview behavior. A source hash or a
loader count alone never established that those earlier ports preserved intent.

A few concrete exceptions remain: incompatible runtime paths, malformed source
links or demonstrated correctness defects, credential discovery, account/session
copying and unrequested external effects. These are explicit bindings or narrow
patches, with originals retained. Unsupported capabilities remain unavailable;
never silently weaken a source's required review or call an unrun workflow tested.

Reference-only and rejected sources remain outside skill discovery. Private or
rights-restricted source packs remain outside public nstack Git. Native generated
memories and the private knowledge vault are never publication inputs.

See [Council](COUNCIL.md) and [SkillSpector](SKILLSPECTOR.md) for their specific
source and activation boundaries. Static review, file integrity and actual runtime
acceptance are different checks; keep each one's coverage limits.
