# On-demand workflows

For clipping and video editing, [media editing](../integrations/media-editing/README.md)
distinguishes the minimal P230 fixture encoder from a verified full FFmpeg build,
frame/sample clocks, captions, audio delivery and editable timeline evidence.
Auto-editor's installed method is separate from native executable admission;
the reviewed candidate remains blocked by Gatekeeper. Keep that limitation
explicit rather than treating a prepared runtime or parsed XML as editor acceptance.

For CPU quantum circuits, open-system physics and differentiable models, use
the existing Qiskit, QuTiP and PennyLane skills with the optional shared
[local quantum environment](../integrations/quantum/README.md). Its small
analytic checks are real acceptance; hardware and large algorithms need their
own verification. [Creative reframing](../addons/creative-reframing/SKILL.md)
can improve a weak assumption or approach without adding a controller or
requiring a brainstorming block in every answer.

For a formal proof, enable `lean-proof` in the math project. Ask 01 for the mathematical result in your own words. The method checks the exported theorem against the intended statement and audits its assumptions. For consequential proofs, it also explains how to replay the export in Nanoda with an explicit axiom policy. [Proof acceptance](../registry/lean-proof/references/proof-acceptance.md)

For RTL/FPGA work, `--fpga` adds the full engineering method, including width,
arithmetic, handshake, CDC and timing considerations. The optional
[Icarus/Yosys runtime](../integrations/fpga/README.md) provides CPU simulation and
synthesis; its checked fault-detection fixture is separate from board signoff.
`--cirq` adds [Cirq](../integrations/cirq/README.md) for device-aware circuits,
noise and characterization alongside the existing three quantum methods.
`--formal-verification` adds pstack's authoring and maintenance methods: turn a
consequential real-code promise into a runnable check, challenge it with a real
mutation, and keep its model/code mapping current. It does not create global
hooks or certify arbitrary software.

`--dream-loop` adds [visual target development](../integrations/dream-loop/README.md):
implement an actual reference, compare fresh captures with independent critique,
and refine or stop using the original quality, performance and stall criteria.
It reuses useful existing visual tools rather than adding another controller.

For agent applications, the existing OpenAI Developers `agents` skill covers
the [Agents API and SDK](https://developers.openai.com/api/docs/guides/agents-api/overview),
while [LangChain/LangGraph](../integrations/ai-workflows/README.md) provides the
tested offline tool and durable-state route. Use the installed Eve method for a
product needing persistent sessions/channels; commission it in that project.
[Native Codex integration](https://developers.openai.com/codex/app-server) can
reuse subscription access. Eve's local subscription adapter is source-supported
but unaccepted against the current Codex protocol and cannot be deployed. Current
Lang checks use a scripted model, not inference. Verify the real app's chosen
inference route and model/effort; API billing and deployment are separate choices.

The local AI recipes prefer Docker on the command's current PATH, then look in
existing standard Docker installation locations. This supports nonlogin agent
shells without another Docker install or a global PATH change. The resolved CLI
then runs with an explicit local socket, private configuration and a system-only
PATH, preventing Docker's implicit credential-helper discovery. Fresh typed-tool,
crash/resume and local trace/evaluation checks passed through the fallback; Docker,
Compose and Buildx load with the restricted execution PATH.

For a browser workflow needing persistent MCP state, the existing P061 Playwright
runtime also supplies [Microsoft's MCP server](../integrations/playwright-mcp/README.md).
Its real headless form, delayed-page, isolation and recovery checks passed through
the installed launcher. This route adds no browser/package installation or global
connection and needs no window rearrangement. It does not control native Mac apps.

[terminal-mac](https://github.com/govijr/terminal-mac) remains reference-only for
separately provisioned guest-desktop workflows. Source reviewed at
`74c548f27910ba2d228637780740e5fd3f9e0450`; published `v0.2.0-6` trails that
source. It runs a real macOS VM with separate apps/accounts/permissions, not
the host's current windows or signed-in sessions. Default guest RAM is at least
4 GiB and disk is 64 GiB logical. The reviewed Mac has 32 GiB RAM; 8 GiB is its
Docker VM allocation. A single capped guest is resource-feasible as a future
trial, subject to actual host load. The current release's apps and executables
failed native execution assessment despite valid self-signatures. Clean-guest
acceptance is also pending. No trust override, installer, VM, account or MCP
activation is included in nstack. This is a potential isolation option, not
repair of a host input bug.

These integrations build applications and execute explicitly selected jobs. They do not replace the Codex/OpenCode harness, canonical Obsidian vault or host-owned memory. No service starts automatically. The installer supplies portable recipes; each recipe has its own source locks and acceptance checks. An installed recipe is not proof its runtime is commissioned on another Mac.

Graphify can support Obsidian by turning a verified code relationship into a
short source-linked project note. Keep generated graphs with their project,
rather than exporting every symbol into the canonical vault. The existing
[Graphify guide](../integrations/graphify/README.md#connect-useful-findings-to-obsidian)
describes this connection and the upstream export limits.

Use the complete linked instructions and actual command interface. LangChain/LangGraph are application libraries, not extra background services. Langfuse is optional observability for an application that needs it. Narrow code navigation can keep its existing semantic tools instead of building a graph.

On this private deployment, 01's live runtime search includes descriptions and activation conditions from the installed tool index. New records become discoverable without editing 01 or maintaining a second category list. Readiness and permissions still require inspection; search results do not execute anything.

Licenses and pinned upstream revisions are recorded beside each integration. Runtime data, accounts, secrets, images and local evidence are not included in this repository. Heavy profiles remain stopped until their resource and configuration prerequisites are satisfied.

## REA software analysis

Use [REA](REA.md) for authorized artifact inspection and retained Evidence views.
Its pinned CLI is separate from Craft Anything and RAEA. Install the shared
method with `--rea`; runtime installation and operation checks are explicit.

## Executable research studies

`--research-engines` adds the complete ShinkaEvolve program-evolution methods
and AI Scientist task-qualified study/paper methods. They complement literature
research rather than replace it. Read the [runtime guide](../integrations/research/README.md)
for the exact supported transport, source locks, role boundaries and actual
commissioning status. Methods, runtimes and completed scientific evidence are
separate: optional modes and missing prerequisites do not become ready through
installation alone.
