# Optional security methods

Retain your existing native installation flags and add
`--cloudflare-security-audit --strix`. Each adds one discoverable skill, shared
by Codex and OpenCode. 01 can select them from live descriptions. Neither
changes the selected model, credentials, host permissions or routine review.

[Cloudflare security-audit-skill](https://github.com/cloudflare/security-audit-skill/tree/c1c8a8c1471069fb0e188eeaff69b8e8db6564a8)
is a repository audit method, not a Cloudflare account integration. Its licensed
support library, report schema and offline validators are included. Native
scheduling retains all reconnaissance lenses and independent validation.
Running target code requires the method's actual isolation and artifact
promotion controls; installing the skill does not create those controls.
Validator fixtures test report mechanics, not security coverage of a real target.

[Strix](https://github.com/usestrix/strix/tree/685bbc8138d35fc9fe378ac37ec0d9198b9c46a3)
is exposed as one Strix-specific entry with nine consumer-method references,
not nine overlapping generic security triggers. The Apache-2.0 source and
modification records are included. Its scanner, Docker environment and cloud
service are not installed or started by this flag. A real task must establish
an authorized target and feasible runtime/provider route first. No automatic
cloud fallback, signup, source upload, payment or credit top-up is enabled.
Strix's response-level budget check is a soft limit that can overshoot, not a
provider-enforced hard spending ceiling.

Existing Codex Security, CodeQL and Semgrep remain available. Select the method
that fits the task rather than running every scanner. Credentials, private
source and live targets require their existing authority and data boundaries.
